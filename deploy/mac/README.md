# Сайт на Mac Ильи

Схема: сайт (Node.js) работает как служба macOS на `127.0.0.1:3000`, nginx принимает 80/443 и отдаёт его наружу по HTTPS, сертификат бесплатный от Let's Encrypt и продлевается сам. Блог сам читает канал раз в день, в 04:00, через прокси VPN. Docker не нужен.

## Что должно быть готово заранее

1. **Белый IP и проброс портов.** IP в настройках роутера должен совпадать с тем, что показывает 2ip.ru. На роутере закрепите за Mac постоянный адрес в локальной сети (DHCP-резервирование) и пробросьте на него порты 80 и 443.
2. **DNS в reg.ru.** A-записи `@` и `www` указывают на этот внешний IP. Проверка: `dig +short itpy.online` возвращает его.
3. **VPN в режиме прокси.** Это обязательно, подробности ниже.
4. **Mac не спит.** Скрипт отключит сон, но MacBook с закрытой крышкой всё равно уснёт. Крышку держите открытой или подключите внешний монитор и питание.
5. **Автовход.** Если VPN — обычное приложение, оно работает только после входа в учётную запись. Включите автоматический вход: «Настройки → Пользователи и группы», а VPN-клиент добавьте в объекты входа.

## VPN: только прокси, не «весь трафик»

Если VPN заворачивает в туннель весь трафик (TUN, «системный VPN»), ответы посетителям сайта тоже уйдут в туннель, и сайт снаружи перестанет открываться. Поэтому:

- Переключите клиент в **режим прокси** и найдите в его настройках **локальный HTTP-прокси**: адрес вида `127.0.0.1:порт`. У v2rayN/Happ это обычно `10809`, у Clash и Hiddify — порт «mixed». Эту строку впишите в `TELEGRAM_PROXY` в `~/itpy/site.env`, например `http://127.0.0.1:10809`.
- Через прокси сайт отправляет только запросы к Telegram, всё остальное идёт напрямую.
- Если клиент умеет только TUN (Amnezia, Outline, WireGuard), включите в нём раздельное туннелирование: через VPN пускать только `t.me`, `telesco.pe` и `cdn-telegram.org`. Тогда `TELEGRAM_PROXY` оставьте пустым.

Проверка из Терминала: `curl -sx http://127.0.0.1:10809 -o /dev/null -w '%{http_code}\n' https://t.me/s/informatika_kege_itpy` должен вернуть `200`.

## Установка

```bash
# 1. Homebrew (если нет) — команда с https://brew.sh
# 2. Node.js 24 и git
brew install node@24 git
echo 'export PATH="$(brew --prefix node@24)/bin:$PATH"' >> ~/.zprofile && source ~/.zprofile

# 3. Код. Не в «Рабочий стол», «Документы» или «Загрузки»: службам macOS туда нельзя.
mkdir -p ~/itpy && git clone git@github.com:Miroslav988/itpy-site.git ~/itpy/site
cd ~/itpy/site && git checkout redesign-blank-ege

# 4. Первый запуск создаст ~/itpy/site.env и остановится
deploy/mac/install.sh
nano ~/itpy/site.env     # DOMAIN, CERT_EMAIL, TELEGRAM_PROXY

# 5. Второй запуск всё ставит: сборка, служба сайта, nginx, сертификат, продление, без сна
deploy/mac/install.sh
```

Если репозиторий приватный, Mac'у нужен доступ только на чтение. В GitHub: Settings → Deploy keys → ключ из `ssh-keygen -t ed25519`, созданного на Mac.

Скрипт спрашивает пароль Mac, когда ставит службы. Повторный запуск ничего не ломает: уже сделанные шаги он пропускает.

## Обновление

```bash
~/itpy/site/deploy/mac/update.sh
```

Скрипт забирает код из git, собирает и перезапускает сайт. Если новая сборка не запустилась, возвращается предыдущая. Посты блога лежат отдельно (`~/itpy/blog`), обновления кода их не трогают.

## Где что лежит

| Что | Где |
|---|---|
| Код | `~/itpy/site` |
| Собранный сайт, который сейчас работает | `~/itpy/app` |
| Настройки | `~/itpy/site.env` |
| Посты и картинки блога | `~/itpy/blog` |
| Логи сайта и синхронизации блога | `~/itpy/logs/site.log` |
| Логи nginx и продления сертификата | `~/itpy/logs/nginx.log`, `certbot.log` |
| Конфиг nginx | `$(brew --prefix)/etc/nginx/servers/itpy.conf` |
| Службы | `/Library/LaunchDaemons/online.itpy.{site,nginx,certbot}.plist` |

## Если что-то не так

- **Сайт не открывается снаружи, а `curl -I http://127.0.0.1:3000` отвечает:**
  - проверьте проброс портов на роутере;
  - проверьте режим VPN (только прокси);
  - если в «Настройки → Сеть → Файрвол» файрвол включён, разрешите входящие подключения для nginx.
- **Блог не обновляется:** `grep "blog sync" ~/itpy/logs/site.log`. Ошибка `ECONNREFUSED` значит, что VPN-клиент не запущен или порт прокси другой.
- **Весь блог заново:**
  ```bash
  cd ~/itpy/site && set -a && . ~/itpy/site.env && set +a && npm run blog:sync -- --all
  ```
- **Перезапустить сайт:** `sudo launchctl kickstart -k system/online.itpy.site`.
- **Убрать всё:**
  ```bash
  sudo launchctl bootout system/online.itpy.site
  sudo launchctl bootout system/online.itpy.nginx
  sudo launchctl bootout system/online.itpy.certbot
  ```
  Затем удалите plist-файлы из `/Library/LaunchDaemons`.
