# Сайт на сервере cloud.ru

Схема:
- **Сайт.** Node.js работает как служба systemd на `127.0.0.1:3000`.
- **nginx.** Принимает порты 80 и 443 и отдаёт сайт наружу по HTTPS.
- **Сертификат.** Бесплатный, от Let's Encrypt, продлевается сам.
- **Блог.** Раз в день читает Telegram-канал, при необходимости через VPN на Mac Ильи ([deploy/tunnel](../tunnel/README.md)).

Docker не нужен. Скрипты проверены на чистой Ubuntu 24.04 с systemd.

## Сервер

На cloud.ru (Evolution) создайте виртуальную машину:
- **Образ:** Ubuntu 24.04.
- **Размер:** 2 vCPU, 4 ГБ памяти; гарантированной доли 10% хватает. Подойдёт и бесплатная машина из free tier.
- **Диск:** 20–30 ГБ.
- **Публичный IP:** включить, он статический.
- **Вход:** по SSH-ключу.
- **Группа безопасности:**
  - входящие подключения на порты 22, 80 и 443;
  - исходящие — все.

Меньше 4 ГБ памяти брать не стоит: сборке сайта может не хватить.

## Установка

```bash
ssh <пользователь>@<IP сервера>
git clone https://github.com/Miroslav988/itpy-site.git ~/itpy/site
cd ~/itpy/site && git checkout redesign-blank-ege

# Первый запуск создаст ~/itpy/site.env и остановится
deploy/server/install.sh
nano ~/itpy/site.env     # DOMAIN, TELEGRAM_PROXY; CERT_EMAIL — когда домен будет вести на сервер

# Второй запуск ставит всё: Node.js, nginx, certbot, сборку, службу сайта, сертификат
deploy/server/install.sh
```

Скрипт запускается под обычным пользователем, `sudo` он вызывает сам. Повторный запуск ничего не ломает: уже сделанные шаги он пропускает или повторяет без вреда.

Пока A-записи домена не ведут на сервер или не указан `CERT_EMAIL`, сертификат пропускается, и сайт открывается по `http://<IP сервера>`. Так его удобно проверить до переключения домена. Когда домен готов, запустите `install.sh` ещё раз.

## Домен в reg.ru

A-записи `@` и `www` указывают на IP сервера. Проверка: `dig +short itpy.online` и `dig +short www.itpy.online` возвращают его. После этого запустите `install.sh`: он получит сертификат и включит HTTPS.

## Telegram

Сначала проверьте на сервере, открывается ли канал напрямую:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://t.me/s/informatika_kege_itpy
```

- Если `200`, `TELEGRAM_PROXY` оставьте пустым.
- Если нет, настройте туннель через Mac Ильи по [deploy/tunnel/README.md](../tunnel/README.md):
  1. положите ключ Mac в `~/itpy/tunnel.pub`;
  2. запустите `install.sh` ещё раз;
  3. укажите `TELEGRAM_PROXY=http://127.0.0.1:10809`.

## Обновление

```bash
~/itpy/site/deploy/server/update.sh
```

Скрипт забирает код из git, собирает и перезапускает сайт. Если новая сборка не запустилась, возвращается предыдущая. Посты блога лежат отдельно (`~/itpy/blog`), обновления кода их не трогают.

Главная страница и карта сайта пересобираются в фоне не реже раза в час, так что новые посты появляются на них без выкатки.

## Где что лежит

| Что | Где |
|---|---|
| Код | `~/itpy/site` |
| Собранный сайт, который сейчас работает | `~/itpy/app` |
| Настройки | `~/itpy/site.env` |
| Посты и картинки блога | `~/itpy/blog` |
| Node.js | `~/itpy/node` |
| Служба сайта | `/etc/systemd/system/itpy-site.service` |
| Конфиг nginx | `/etc/nginx/sites-available/itpy.conf` |
| Сертификат | `/etc/letsencrypt/live/<домен>` |

## Если что-то не так

- **Логи сайта и синхронизации блога:** `journalctl -u itpy-site -f`. Только блог: `journalctl -u itpy-site | grep "blog sync"`.
- **Перезапустить сайт:** `sudo systemctl restart itpy-site`.
- **Сайт не открывается снаружи, а `curl -I http://127.0.0.1:3000` отвечает:**
  - проверьте, что в группе безопасности открыты порты 80 и 443;
  - посмотрите `sudo nginx -t` и `sudo journalctl -u nginx`.
- **Сертификат:**
  - `sudo certbot certificates` — какие есть;
  - `sudo certbot renew --dry-run` — проверка продления;
  - продлевает его `certbot.timer`, после продления nginx перезагружается сам.
- **Весь блог заново:**
  ```bash
  cd ~/itpy/site && set -a && . ~/itpy/site.env && set +a && PATH=~/itpy/node/bin:$PATH npm run blog:sync -- --all
  ```
- **Обновления безопасности Ubuntu** ставятся сами (unattended-upgrades). Перезагрузка сервера сайт не ломает: служба и nginx стартуют сами.
